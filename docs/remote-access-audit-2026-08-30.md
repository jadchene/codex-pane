# 远程访问改造与七轮审查记录

日期：2026-08-30—2026-08-31
范围：桌面 Remote Bridge、Thin Relay、手机 Bootloader 与手机业务页面

## 结论

改造已形成三层边界：Relay 只保存内存通道并透传不透明帧；桌面负责设备、Passkey、端到端加密、手机协议和 app-server 翻译；手机只提供会话、纯文本和单次审批能力。桌面安装包携带与自身版本匹配的手机页面，普通业务升级不要求更新 Relay。

真实端到端用例已覆盖：桌面连接 Relay、生成二维码、拒绝陌生设备、手机创建 Passkey、桌面核对确认码、Passkey 登录、E2EE、桌面下发页面、查看与切换会话、发送消息、撤销手机并阻止继续访问。

## 第一轮：首次启用与绑定流程

从“部署 Relay → 桌面填写地址 → 生成二维码 → 手机创建 Passkey → 桌面确认”的首次使用路径审查。

发现并修正：

- 删除旧架构遗留的首次绑定密钥、Cookie、账号和 SQLite 说明，设置中只保留 Relay 地址。
- 二维码秘密放在 URL Fragment 中，短时有效；Relay HTTP 日志不会收到 Fragment。
- 手机 Passkey 登记完成后，桌面必须显示并确认同一组 6 位数字，登记才写入本地设备列表。
- 修复 Bootloader 异步点击后继续读取失效事件对象的问题，避免 Passkey 操作结束后按钮状态异常。
- 撤销设备后，手机会删除本地绑定并明确提示重新扫码，不停留在不可恢复的空白页。

证据：设置组件测试、IPC 边界测试、真实端到端绑定与撤销流程。

## 第二轮：日常会话操作

从“手机登录 → 查看最近会话 → 切换会话 → 发消息 → 接收状态”的日常路径审查。

发现并修正：

- 手机页面可能在初始快照到达后才装载，原实现会丢失会话列表；Bootloader 现会排队 UI 事件，页面就绪后再次主动请求快照。
- 原抽屉组件在沙箱 Blob iframe 中行为不稳定，改为由 Vue 状态控制的轻量侧栏。
- 会话页面和快照的竞态测试使用真实可见手机窗口，避免不可见 Electron 窗口不投递子页面触控所产生的假失败。
- 长内容跟随底部只在用户接近底部时生效，用户上翻后不会被新消息强制拉回。

证据：手机端单元测试 4 项通过；真实流程成功打开“示例会话 A”并由 fake app-server 收到对应 `turn/start`。

## 第三轮：陌生连接、密文与权限边界

从“攻击者扫描 Relay、伪造设备、篡改或重放消息、构造高危命令”的对抗视角审查。

确认与补强：

- 桌面以 P-256 身份签名建立通道；手机必须使用已登记设备签名或短时配对秘密通过 Relay 准入。
- 每次连接重新进行临时 ECDH，使用 HKDF-SHA-256 派生 AES-256-GCM 会话密钥。
- 会话 ID 与严格递增序号进入 AAD；重放、错序、不同会话和密文篡改均被拒绝。
- 手机协议只有快照、列出/打开/新建会话、发送纯文本和单次审批六类命令；未知类型和超长文本在桌面白名单解析前被拒绝。
- 远程审批只允许命令确认和 URL 型 MCP 请求；结构化 MCP 表单及其他 server-request 留在桌面处理。
- Relay 对帧大小、连接数、通道数、每通道手机数、速率、心跳和发送背压设限。

证据：陌生设备真实连接被 1008 拒绝；密码学篡改/重放测试、协议白名单测试、审批协调测试及 Relay 授权测试通过。

## 第四轮：生命周期、数据与故障恢复

从“多手机、退出、撤销、Relay 重启、桌面退出和本地数据故障”的维护路径审查。

确认与补强：

- Relay 不落用户、Passkey、设备、Session 或消息数据库；进程重启后双方重新连接。
- 每部手机拥有独立设备密钥、Passkey 记录和会话密钥；撤销只影响目标手机。
- 桌面长期私钥由 Electron `safeStorage` 加密，无法安全加密时拒绝启用远程访问。
- 新增有界本地安全审计，记录绑定、撤销、认证、拒绝和审批结果，不记录提示词、消息正文或命令输出；审计写入失败不会破坏已经完成的用户操作。
- 桌面关闭时停止 Relay 重连计时器、释放远程会话订阅并清理待处理状态。
- 修复“退出所有手机”使用浏览器 WebSocket 不允许的关闭码而直接报错的问题，并在重连前恢复引导页，确保用户能再次点击 Passkey 登录。

证据：本地凭据与审计单元测试、撤销端到端流程、双实例退出回归通过。

## 第五轮：部署稳定性与发布产物

从“Relay 部署一次后长期不动、桌面升级、Windows 包可运行”的发布路径审查。

确认与补强：

- Relay 公网业务面只有固定静态 Bootloader、`/health` 和 `/ws`，没有用户、设备、登录、会话或 app-server API。
- 手机业务页面由桌面通过已认证 E2EE 会话下发；会话协议和 UI 更新只进入桌面安装包。
- 桌面为手机页面生成 SHA-256 清单摘要并用桌面身份密钥签名；Bootloader 验证摘要与签名后才执行页面，并按内容摘要缓存已验证版本。
- Docker Compose 只有 Caddy 证书与配置卷，Relay 无业务数据卷。
- Windows `win-unpacked` 构建成功；ASAR 已确认包含 Remote Bridge、密码学、Passkey、本地凭据模块和 `remote/mobile/dist-bundle/mobile.html`。
- 原有 E2E 运行器在当前 Windows 环境中会因不可见/独立 GPU 子进程崩溃，统一使用软件渲染与进程内 GPU 参数后，缺少 Codex、双实例、会话侧栏、性能和远程链路回归均可稳定执行。

打包后的实时 Codex 冒烟仍受本机账号状态影响：当前 app-server 返回“需要 ChatGPT 身份验证”，因此依赖模型列表和输入框的既有实时用例无法完成。这不是 Relay、Remote Bridge 或手机链路错误；登录恢复后应补跑 `npm run test:packaged`。

## 第六轮：连接准入、身份状态与配置边界

再次从公网连接耗尽、会话状态复用、配对中断和配置注入角度审查。

发现并修正：

- 未完成身份附加的 WebSocket 现在会随 Relay Challenge 到期主动关闭，陌生连接不能仅靠持续响应心跳长期占用全部连接名额。
- 已登录设备重新发起临时会话握手时，桌面会先清除旧的 Passkey 登录态；新会话必须重新完成 Passkey 验证。
- Passkey 认证结果只有在新计数器和最后使用时间成功持久化后才生效；保存失败不会留下已认证但未完成登录的内存状态。
- 配对过程遇到瞬时断线会在二维码有效期内自动重连，不再停留在不可恢复的等待状态。
- Relay 地址限定为纯 HTTPS Origin，本机调试可使用纯 HTTP Origin；拒绝用户名、密码、路径、查询和 Fragment，避免 URL 凭据进入配对二维码。

证据：IPC 地址边界测试、Relay 类型检查与构建、根项目完整测试和真实远程端到端流程通过。

## 第七轮：异步顺序、失败恢复与供应链

再次从高频操作、异步密码学、失败重试、静态入口依赖和部署兼容性角度审查。

发现并修正：

- 桌面按手机连接串行处理密文和命令，快速连续执行“切换会话 → 发送消息”不会并发落到旧会话，重复请求也不会在同一连接内并行执行。
- Bootloader 串行执行 Web Crypto 加密和 WebSocket 发送，严格保持 AES-GCM 序号与网络帧顺序一致；连接切换后，旧会话中的待发送任务会被拒绝。
- Passkey 或安全握手失败时会显示明确错误和“重新连接”入口；手机业务页面已加载后发生协议错误时，会收到断开状态而不是静默失效。
- npm 官方审计发现 Relay 的旧版 `@fastify/static` 存在高危路径绕过与目录遍历问题；已升级至与 Fastify 5 兼容的修复版本 `10.1.3`。
- 根项目、Relay 和手机端的完整依赖树经 npm 官方端点复核，均为 0 个已知漏洞。
- 复核发现性能用例没有实际使用其他 Electron 回归已有的软件渲染参数，已补齐；六窗格最长会话性能用例随后连续两次通过。

证据：新增串行任务顺序与失败恢复测试；根项目、Relay、手机端完整测试和构建通过；升级后的真实绑定、Passkey、E2EE、会话、重连与撤销流程通过。

## 第八轮：桌面多实例与退出恢复

从同一数据目录同时启动多个桌面窗口、退出管理实例和重新接管远程访问的用户流程审查。

发现并修正：

- 多个应用实例原本会同时连接同一 Relay 通道，后启动实例会把手机和先启动实例踢下线。现在以进程租约保证同一数据目录只有一个 Remote Bridge 管理实例。
- 非管理实例仍可正常使用本地工作台，但远程设置、配对、撤销和全端退出均为只读，并明确说明当前由另一实例管理。
- Electron 安全存储上下文不支持已作为次实例启动的进程无感解密主实例密钥，因此不做不可靠的自动接管。关闭管理实例后，用户重启保留窗口即可安全接管。
- 退出时先断开远程连接并释放租约；Windows 进程树清理增加五秒上限，避免异常子进程使应用永久卡在退出阶段。

证据：新增租约竞争、释放和陈旧租约恢复测试；真实远程端到端用例覆盖双实例不抢占、手机连接保持、管理实例退出、重启接管并重新连接 Relay。
